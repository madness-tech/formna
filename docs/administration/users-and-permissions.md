## Role model

| Role | Capabilities |
|---|---|
| Super Admin | full system administration, settings, branding, integrations, audit access |
| Admin | form and program management, own-area reviews, user management as allowed |
| Reviewer | assigned review work, decisions, clarification participation |
| User | end-user submission and account access |

---

## Creating and editing users

Administrators can create users by entering:

- first name
- last name
- email address
- role
- timezone

Typical outcomes:

- account record is created
- a verification or onboarding email is sent
- the user completes password setup or verification steps

Administrators can also edit user profile details, role, and status.

---

## Account controls

Documented administrative account controls include:

- password reset initiation
- deactivation or reactivation
- MFA reset
- activity inspection through user detail and audit records

Use these controls carefully and log internal support procedures where required by policy.

---

## Form-specific permissions

Instead of assigning a broader global role, administrators can grant targeted access to a specific form. Common permission levels include:

- view
- review
- admin

This is useful for distributed teams where a subject-matter owner needs control of one form without becoming a full platform admin.

---

## Governance recommendations

- apply least-privilege access
- review elevated permissions regularly
- deactivate dormant internal accounts promptly
- document who owns major forms and programs
- prefer form-specific access over unnecessary global role changes
